### 4. RLS default-deny confirmed on every table: **N/A as written, requirement MET in substance**

The brief assumes Supabase. The app tier is Convex, where there is no row level
security because there is no direct table access at all: the browser can only
call named functions, and every one of them authenticates before reading.

That is a stronger posture than default-deny RLS, not a weaker one, but it is a
different mechanism and this line should be rewritten rather than ticked.

### 5. Restricted fields have a named owner who approved teacher-level visibility: **NO**

Nobody has approved anything, so nothing is visible. Default deny for every
role, and the restricted data is not loaded at all.

The brief's own closing question is unanswered: **what decision do federal
ethnicity and federal race inform in a teacher-facing dashboard?** If nobody
can name one, the brief's recommendation is to descope them. That answer needs
a person, not a commit.

### 7. Wildcat Hub is named in the organization's data governance documentation: **NO**

### 8. Runbook exists and a second person has read it: **NO**

Half of it now passes. `docs/runbook.md` is written and covers all four things
the brief asks for: re-running a failed sync, rolling back a bad load, who to
contact when PowerSchool credentials expire, and rotating the client secret.

The line still fails on its second clause. **Nobody has read it but its author.**
That is the point of the clause: a runbook one person wrote and one person
understands is not an operational document. It needs a second reader who can
follow it without asking the author anything.

### 9. Secrets are in the secret store, absent from repo history: **YES**

- PowerSchool client id and secret: 1Password, referenced as `op://` in `.env`,
  and set as Convex deployment environment variables. Never in a file.
- Convex deploy key: 1Password.
- Entra and Google client IDs are in the repo deliberately. They are not
  secrets: they ship in the page source and appear in every token. Neither
  client SECRET is used by these flows or present anywhere.
- **Verified across all 802 commits** by exact-string match of the real secret
  values, not by pattern guessing. No hit. `.env` is untracked.

### 10. Rollback path is tested, not just documented: **NO**

A backup is taken before each destructive write (`purge-cleartext-passwords`
writes one; the Firestore email patches wrote one). Restoring from one has
never been rehearsed, so the path is documented-ish and untested.

None of the above says the pipeline is broken. It says the assurance around it
is incomplete.

- Plugin installed and authenticating: `plugin_id` 9741, version 1.0.6
- All 7 PowerQueries installed and returning rows
- 641 students, 3805 enrollments, 145 sections, 29 teachers, 644 attendance rows
- Syncing twice daily from Convex, server side, verified by running it
- Read only by construction: the only calls are the OAuth token request and
  POSTs to named query paths

  is the property that mattered most
