# Runbook: Wildcat Hub SIS sync

Covers the four things the brief asks for: re-running a failed sync, rolling
back a bad load, who to contact when credentials expire, and rotating the
client secret.

Written 2026-08-12. **Nobody has read this but its author**, which is itself a
go/no-go line. Second reader needed.

## What runs, and when

| | |
|---|---|
| Schedule | Twice daily, 13:00 and 19:00 UTC (06:00 and 12:00 PT) |
| Where | Convex, deployment `quick-cassowary-644`, `convex/crons.ts` |
| What it calls | `sisAction:syncFromPowerSchool` |
| Source | `lapf.powerschool.com`, plugin id 9741 |
| Read only | Only the OAuth token request and POSTs to named query paths |

The clock is UTC, so the local time shifts an hour at the DST boundary. Both
runs stay inside the school day either way.

## Check whether the last sync worked

```
export CONVEX_DEPLOY_KEY=$(op read 'op://Employee/Westbrook WildCats Hub/Convex wildcat-hub-ci Deploy Key')
npx convex run sisStats:stats '{}'
```

Healthy looks like roster rows in the thousands, `rosterStudents` around 641,
and a recent `lastSyncedAt`. `syncLog:latest` has the last five run summaries.

`gradeRowsMissingPercent` equal to `gradeRows` is EXPECTED right now: the 26-27
year began 2026-08-12 and no grades are posted. It is a gap, not a zero, and
must never render as 0%.

## Re-run a failed sync

Safe to run any time. Roster is a full replace, students upsert on student
number, and nothing it writes is earned value.

```
npx convex run sisAction:syncFromPowerSchool '{"reason":"manual re-run"}'
```

Locally, with more output and a dry-run option:

```
cd powerschool/sync
npm run sync -- --dry     # pull and report, write nothing
npm run sync              # for real
```

## Roll back a bad load

There is no snapshot restore for Convex here, so rollback is "re-sync from the
source", which works because PowerSchool is authoritative for everything the
sync writes.

1. Re-run the sync. Roster and grades are full replaces, so a bad load is
   overwritten rather than merged with.
2. If student identity looks wrong, re-run and check `sisStats:stats`.
3. **Balances are never touched by a sync**, so they cannot be damaged by one.
   If a balance looks wrong, the sync is not the cause; check `npm run drift`
   against Firestore.

⚠️ **Untested.** This path has never been rehearsed on real damage. That is a
go/no-go line still open.

### When PowerSchool credentials expire or stop working

Symptom: `PowerSchool auth failed: HTTP 401` in the sync run.

Contact: the PowerSchool / SIS administrator for LA Promise Fund. The plugin is
"Wildcat Hub Sync", id 9741. Credentials are issued by PowerSchool when the
plugin is enabled, and are regenerated by disabling and re-enabling it.

### Rotate the client secret

1. PowerSchool: System > System Settings > Plugin Management Configuration >
   Wildcat Hub Sync. Disable, then re-enable. PowerSchool issues a new secret.
2. Update 1Password: `SIS Client Secret` on the `Westbrook WildCats Hub` item.
3. Update Convex, so the scheduled sync uses it:
   ```
   npx convex env set PS_CLIENT_SECRET "$(op read 'op://Employee/Westbrook WildCats Hub/SIS Client Secret')"
   ```
4. Verify: `npx convex run sisAction:syncFromPowerSchool '{"reason":"post-rotation check"}'`

Never paste a secret into a file, a commit, or a chat. The repo is public.

## When something looks wrong

| Symptom | First thing to check |
|---|---|
| Sync ran, roster count dropped sharply | A term rolled over. `PS_TERM_ID` and `PS_YEAR_TERM_ID` are pinned per term and go stale each year. |
| All grades empty | Expected before grades are posted. Confirm with the `terms` query. |
| A teacher sees no roster | Their Entra email must match `psRoster.teacherEmail`. Check `npx convex run seed:staffAuthReadiness '{}'`. |
| A student cannot sign in | Expected. Student email does not exist in the SIS at all. |
| Balances look wrong | Not the sync. Run `npm run drift`. |

## Reflection Room list (lunch detentions)

Added 2026-10-08 (build spec revision 2, with the owner's answers of
10/8). The list says who serves a Reflection Room lunch detention each school
day: unexcused tardies (`T`) between class periods, plus uniform entries. It
is **switched off** until somebody turns it on from the command line, and a
missing settings row means off.

### What runs, and when

| | |
|---|---|
| Cron | `reflection tick`, every 5 minutes, 14:00-23:55 UTC (`convex/crons.ts`) |
| What it calls | `reflection:tick`, which books `reflectionRead:read` when a read is due |
| Local times | Decided by the handler on the Los Angeles clock, never by the UTC hour the cron fired |
| While off | Both divisions off: the tick reads one settings row and stops. Nothing is read from PowerSchool |

The day's reads (LA time): opening 07:30 (also takes the roster snapshot),
08:30, 09:30, 10:30, four pre-close reads, then the **closing read** from the
close (11:45 regular, 11:20 Wednesday and Minimum, 11:50 Stack), after-close
13:00/14:00/15:00 and after-school 15:45. The list is made by the first closing
read that is confirmed (two PowerSchool reads in a row that agree on every
row). If none worked by the ready time (12:00, or 11:30 Wednesday and Minimum)
it is made from the last good read ("fallback"). From 10 minutes before Lunch
& Power-Up (12:21 / 11:32 / 12:12) nothing can make it: the day shows "No list
today" and everything moves to the next school day's list by itself.

### Switching it on, per division

Every command names the deployment, because `.env.local` points at production.

```
# Shadow pilot: lists are made and watermarked PILOT, nobody is pulled
npx convex run --prod reflection:setMode '{"division":"ms","mode":"shadow","countFromDate":"2026-10-21"}'
npx convex run --prod reflection:setMode '{"division":"hs","mode":"shadow","countFromDate":"2026-10-21"}'

# Live, one division at a time (HS stays in shadow as the control)
npx convex run --prod reflection:setMode '{"division":"ms","mode":"live","countFromDate":"2026-11-09"}'

# Rollback: no deploy needed, the tables stay for review
npx convex run --prod reflection:setMode '{"division":"ms","mode":"off"}'
```

`countFromDate` defaults to the next school day. Violations dated before it
are stored as `before-start` and never listed, so switching on (or back on
after a pause) never floods the first list. While a division is **off** its
tardies and uniform entries are kept as they read and wait on no list; the
other division's list leaves them alone. Switching it on parks everything
dated before `countFromDate` and counts the rest, so a division switched on
the same morning, counting from today, takes that morning's tardies and
uniform entries (the evening before is still the quiet time to run it).
Going from shadow to live sets a
new date: pending shadow items before it become `before-start`, and shadow
carries do not move into live. Only what is from before the start is parked:
a rollback switched back on the same afternoon, counting from that day, keeps
that day's queued second detentions and carries (a carry decided while the
division was off waits for the switch too). A date corrected to an earlier
one (a morning `setMode` with no date counts from tomorrow; run it again with
today's date) gives back the tardies and uniform entries the later date had
parked. Every mode change is written to `reflectionAudit`.

Other settings (close minutes, `lateEntryLists`, `maxCarries`, counting
ditching or Power-Up tardies, `holdFirstClassOnPtNoRow`, capacity, the swap
minute, the HS pull lead and the MS pull lead) are changed the same way,
never from a screen in v1. A value that does not make sense falls back to the
default and is named in the answer's `refused`:

```
npx convex run --prod reflection:saveSettings '{"holdFirstClassOnPtNoRow":true}'
# The room runs during lunch, MS first (owner, 10/8). HS is pulled from
# Power-Up 5 minutes before the swap, which is the block's midpoint (13:02
# regular, 12:13 Wednesday and Minimum, 12:53 Stack):
npx convex run --prod reflection:saveSettings '{"swapMinuteByKind":{"regular":785},"hsPullLeadMinutes":5}'
# MS is pulled from the class before lunch this many minutes before Lunch &
# Power-Up starts (owner, 10/9; default 2: 12:29 regular, 11:40 Wednesday and
# Minimum, 12:20 Stack). It must stay under lastFreezeMarginMin (10):
npx convex run --prod reflection:saveSettings '{"msPullLeadMinutes":2}'
npx convex run --prod reflection:status '{}'          # today's state: reads done, last good read, list made?
npx convex run --prod reflection:rosterStatus '{}'    # snapshot age and the term banner
```

### Who sees it, the review queue, and the audit trail

The screen is Discipline > Reflection Room, for admin, superadmin and PBIS,
and for anyone an admin gives the list to on the Teachers tab (Edit >
"Reflection Room list"), until a last day: blank means the end of the term,
read from PowerSchool. A grant holder may view and print the list and take the
room's attendance; never the review queue, the settings, "Read PowerSchool
now", the school-day mark, "Room did not run today" or uniform logging. A role
change removes the grant. Admins see every holder and their last day under
"Who can see this list" on the screen. From a terminal:

```
npx convex run --prod staffInvites:setStaffReflectionListFromCli '{"email":"someone@lapromisefund.org","on":true}'                       # until the end of the term
npx convex run --prod staffInvites:setStaffReflectionListFromCli '{"email":"someone@lapromisefund.org","on":true,"until":"2026-11-06"}'
npx convex run --prod staffInvites:setStaffReflectionListFromCli '{"email":"someone@lapromisefund.org","on":false}'
```

The list reads
`reflectionList:listForDay` every 30 seconds while it is open; its Print
button reads the list again, records the print (`reflectionPrints`: ids and
student numbers, never names) and then prints. Ctrl+P (Cmd+P) on that screen
goes through the same Print button. Printing from the browser's own menu
prints the list on screen, unrecorded, and marks every page "STALE" when it
is more than a minute old.

A list that names an MS class before lunch is sent only to a screen that shows
it (`listForDay` with `lunchOk`, from the 2026-10-09 build on). A tab still
running an older screen would head that column "Power-Up" and print the
Power-Up room, so it shows "Middle school is now pulled from the class before
lunch. The list shows it once the Hub updates itself." and has nothing to
print; nobody needs to do anything. Deploy Convex before pushing the site, as
always: an older server refuses the new screen's `lunchOk`.

- **Print slips** (optional, never on the main path): only once the list is
  final. Several teachers to a page with cut lines, MS first: an MS slip goes
  to the teacher of the student's class before lunch (owner, 10/9), an HS slip
  to the Power-Up teacher. Each slip folds to the teacher's name and carries
  only each student's name, number, grade and "Reflection Room today". An RSP,
  Designated ELD or 7002A class is named on the slip, flagged. A class the list
  could not name goes out under "Class before lunch not found — check
  PowerSchool" (or "Check PowerSchool: 2 classes in P3"), never to a guessed
  room.
- **Print changes only** appears when your own print is out of date: the
  students added since it, and a "release this student" list.
- **Room attendance is check-off** (owner, 2026-10-12; roles and grant
  holders), from Lunch & Power-Up start until the next list is made: check
  **Here** next to each student as they arrive (the screen shows "N of M
  here", for the whole list and for each sitting), then press **Attendance
  done**. It first names how many students are not checked and who; every one
  of them moves to their next school day's list ("Carried over from ...
  (absent)" or "(at school: did not come)"), with the same limit of 5 carries
  as before. A check can be taken back until Attendance done is pressed;
  **Undo Attendance done** opens the checks again. A student checked Here is
  served whatever PowerSchool says, even if nobody presses Attendance done;
  the students nobody checked are then decided by PowerSchool, and the review
  queue says "Attendance done not pressed". **Room did not run today** (roles
  only, with a reason) carries everyone without counting toward the limit.
  Each act is kept on the detention or the day, and in `reflectionAudit`. All
  of this applies to the **live** division only: a division in shadow (HS
  during the MS live week) has no box, and PowerSchool decides its carries
  whatever the room presses.
  - **Attendance done moves exactly the students its confirmation named**
    (review, 2026-10-12). If the list changes while it is open (another
    supervisor checks someone in or takes a check back, even swapping one
    student for another), nothing is recorded and it says to press again. A
    student put back on the list after it was pressed (a tardy deleted and
    typed back in PowerSchool) was never named: PowerSchool decides them.
  - A detention an administrator has already decided in review ("Add to next
    list") has no Here box and is not counted.
  - A fix entered the morning after (a check from paper, Undo and Attendance
    done again) counts until the next list is made, even when PowerSchool is
    down and that list is made without it.
  - Taps on one student's box reach the server in the order they were made.
  - **Mon 10/12's list keeps Not here.** It was made before check-off shipped,
    and its room ticked Not here: on it, only ticked students carry. Every
    list made since is stamped check-off when it is made (`roomMode` on
    `reflectionDays`).
  - **A tab still on the screen from before** (stamp 20261012b) is shown the
    list but no Not here box ("This list now uses check-off: the Hub is
    updating itself"), and a Not here tick or Attendance done it sends is
    refused with the same words. Nobody needs to refresh: the tab updates
    itself.
- **Review** (roles only) is the admin review queue: "Add to next list" or
  "Dismiss" (a reason is required), each with its age in school days.
- **Read PowerSchool now** and **This is a school day** (roles only) are on
  Today. Read now respects the lease and runs at most once every 2 minutes;
  between the close and 4 minutes before the ready time it is the closing
  read, which makes the list. "This is a school day" lets the list be made at
  the ready time when PowerSchool cannot show it; on a weekend or a day marked
  no school it is refused (mark the day in Settings > Bell Schedule).
- The **health card** is in Settings > Integrations, beside the attendance
  rebuild: today's list (how and when it was made, how long the closing read
  took), the last good read and any error, the review queue's size and age,
  the roster snapshot and the last sync's roster guard. Counts only.

The same queue and the audit trail from the command line:

```
npx convex run --prod reflectionList:adminReview '{}'                    # each item, with its age in school days
npx convex run --prod reflectionList:auditTrail '{"day":"2026-10-21"}'   # every human act on that day's list
```

The Uniform Tracker files each entry under the school day of the moment Enter
was pressed (the server decides, never the Chromebook), queues and retries a
save that fails, keeps unsent entries on the device for the person who
entered them, and holds an app update while any are unsent. Undo needs a
reason once the entry's list is made.

### A TEST list, to show staff what the list looks like (`reflectionDemo`)

For showing administrators the list in the Hub before it counts (owner,
2026-10-08). It reads one day from PowerSchool (the real reader's confirmed
read: the day, and the previous school day for its P5 and P6 tardies), works
out the list with the shipped rules as if it closed at that moment, and
stores it in `reflectionDemoLists` only. Discipline > Reflection Room shows it
for that day under a red "TEST ONLY — built from today's PowerSchool marks at
H:MM" banner, and every printed page says "TEST — not for assignment". It is
shown only while that day has no real list made (a real list always wins),
no print of it is recorded, and slips and "Print changes only" are off.
Tardies only: no uniform entries, carries or queued detentions.

It is refused for a day the real list counts (a division switched on from on
or before that day), a day whose real list is made, and a future day. If the
switch is moved after it was built so that its day counts, the real list is
shown and printed instead, as if the TEST list were not there.

Only a screen that marks it as TEST is sent its rows (`listForDay` with
`demoOk`, from the 2026-10-08 build on). A tab still running an older screen
shows "This day has only a TEST list. It shows, marked TEST, once the Hub
updates itself." and has nothing to print; nobody needs to do anything. So
it is safe to build at any point after the Convex deploy. Deploy Convex
before pushing the site, as always: an older server refuses the new
screen's `demoOk`.

Building it again replaces it. Clear it once it has been shown:

```
npx convex run --prod reflectionDemo:build '{"day":"2026-10-08"}'   # counts only in the answer
npx convex run --prod reflectionDemo:clear '{"day":"2026-10-08"}'
```

Never at 13:25-14:00 or 19:25-20:00 UTC (the attendance rebuild's windows).

### Checking the list during the pilot (`scripts/reflection-verify.mjs`)

A second, independent reading of PowerSchool, with its own copy of the rules,
that the pilot's controls are judged by. It only reads PowerSchool, prints
counts only, and stores salted hashes (never a student number) in
`~/.wildcat/reflection-verify/`. It needs `PS_HOST`, `PS_CLIENT_ID`,
`PS_CLIENT_SECRET`, `PS_SCHOOL_ID`, `PS_YEAR_ID` and `PS_TERM_ID` in the
environment. Never at 13:25-14:00 or 19:25-20:00 UTC.

```
# At close + 1 minute (11:46 regular, 11:21 Wednesday and Minimum, 11:51 Stack), as a local scheduled task:
node scripts/reflection-verify.mjs snapshot
# After school (it runs npx convex run --deployment prod reflectionList:verifyExport itself):
node scripts/reflection-verify.mjs compare --day 2026-10-21
```

`compare` sorts every difference (on the list, entered late, held, excluded
by rule, rule disagreement, dropped by the reader, corrected after the list
was made, missing), prints the controls that must be 0, and ends with
CLEAN, NOT CLEAN, or NOT JUDGED (no snapshot that day: it neither counts
toward the clean run nor breaks it). Each judged day's counts are kept as
`<day>.result.json` beside the snapshot.

- **No Convex deploys of any kind on school days from 20 minutes before the

  and Minimum 11:00-11:42, Stack 11:30-12:22.
- **During the shadow pilot, the MS live week and the first whole-school

- From 11/2, 19:25-20:00 UTC is 11:25-12:00 PST, inside the list window anyway.
- Deploy in the evening, 17:00-21:00 LA. Before each deploy: fetch, read any

tick carries on.

### The roster: snapshot and empty-clear guard

- The list never reads `psRoster` live. The opening read copies it into
  `reflectionRoster` once a day, and only when the sync that wrote it finished,
  every row has one `syncedAt`, and the student count is at least 90% of the
  last snapshot. Otherwise yesterday's stays and the list says "Power-Up
  teachers from the 10/13 roster". `reflection:rosterStatus` shows the last
  refusal and why.
- A snapshot taken by the code before 10/9 does not keep each slot's class
  whole, so it cannot see a second class in the slot before lunch.
  `reflection:rosterStatus` shows `classBySlot: true` on a whole one. One
  without it is replaced by the next read of any kind, the same day, once:
  on the day this ships, the list made at the close is never made from it.
- **The PowerSchool sync no longer empties the roster on a bad read.** When
  the roster query comes back empty, or with under half the rows already here,
  the sync keeps the roster it has and records `rosterKept: true` and the
  reason in its `syncRuns` summary (`syncLog:latest`). That is a signal to
  investigate (a stale `PS_TERM_ID` is the likeliest cause), not a failure to
  re-run: re-running gets the same answer until the cause is fixed.

## Automatic perfect-day award (Wildcat Cash for perfect attendance)

Added 2026-10-12 (server half, then the site half: the student card line,
the staff screens and the admin card ship with the site stamped `20261012c`). Each school morning the server reads the last fifteen school days
from PowerSchool, finds every student who had a **perfect day** (no absence,
excused ones included, no unexcused tardy, no ditching, in any block, Promise
Time and Power-Up included; an excused tardy and a field trip do not break
it), records it, and every Monday pays one Wildcat Cash movement per student
for last week's perfect days ("Perfect attendance -- N days", by "Wildcat Hub
(attendance)"). It is **switched off** until somebody turns it on, and a
missing settings row means off.

### What runs, and when

| | |
|---|---|
| Cron | `perfect day award`, at :42 past 14, 15, 16 and 17 UTC (`convex/crons.ts`) |
| What it calls | `perfectDay:tick`, which books `perfectDayRead:run` |
| Local times | Decided on the Los Angeles clock: only on a weekday between 06:30 and 11:00 (06:42-09:42 in winter, 07:42-10:42 in summer) |
| Later firings | Run again only when a PowerSchool read failed. A day with no attendance at all is no school, not a failure |
| Payday | The first run on or after Monday pays everything pending from before that Monday. On a Monday it waits until 09:30 for a failed read of last week to be retried, then pays what is settled. Paying needs nothing from PowerSchool: if PowerSchool is down, payday still happens at the 09:42 run (and the run tries the read again next hour) |
| While off | The tick reads one settings row and stops |

### Switching it on

```
# Shadow: decides and records, pays nobody, shows students nothing
npx convex run --prod perfectDay:configure '{"mode":"shadow","actorName":"Your Name"}'

# A named pilot, with controls who must never be paid
npx convex run --prod perfectDay:configure '{"mode":"pilot","pilotAdd":["<student number>"],"controls":["<student number>"],"actorName":"Your Name"}'

# The whole school (the pilot's controls are cleared: controls belong to the pilot)
npx convex run --prod perfectDay:configure '{"mode":"live","actorName":"Your Name"}'

# The kill switch: instant, no deploy; the next batch stops. Days already
# decided as pending are NOT lost: they wait, and are paid on the first payday
# after it is switched back on. To cancel them instead, use forfeitPending.
npx convex run --prod perfectDay:configure '{"mode":"off","actorName":"Your Name"}'

# The amount per perfect day (whole dollars, 1-1000); days already decided keep theirs
npx convex run --prod perfectDay:configure '{"amount":150,"actorName":"Your Name"}'
```

**No back-pay, ever.** Switching on from off counts from that day; a day is
stamped payable or not when it is first decided (shadow days, days outside
the pilot and days of a control never become payable); and moving from pilot
to live pays the rest of the school only from that day. Counting from an
earlier date needs `countFromDate` AND `"backPay": true`.

**And no switch takes back what was earned.** A day stamped payable (shown to
the student as pending) is paid on the next payday that money moves, whatever
the switch did since: off and on again, live to pilot, or a student taken out
of the pilot. Payday does not ask today's start date again. While off, the
status counts those days as waiting ("off"); a control's days wait until the
controls are cleared. And the days decided before a pause are still re-read
by every run while they are in the lookback, exactly like any other: a late
absence is applied before payday (or puts a paid day on the paid-then-broken
list), and a day held for the second check is released once it agrees. What a pause does lose is any school day not yet
decided when it went off: the run decides each day the next morning, so
switching off before Monday's run means Friday is never decided. After a false
alarm the same morning, switch back on with `"countFromDate":"<that Friday>"`
and `"backPay": true` to decide it. To cancel pending days on purpose (the job
decided them wrongly), forfeit them before switching back on:

```
# Counts only; add "apply":true to forfeit (pending and held days in the range become removed, never paid)
npx convex run --prod perfectDay:forfeitPending '{"from":"2026-10-19","to":"2026-10-23","reason":"...","actorName":"Your Name"}'
```

**Before going live: the $5,000 browser cap.** Any single cash movement a
browser saves is refused above $5,000 (`MAX_CASH_DELTA`; the cap fix is
parked). At $100 a day a student with perfect attendance passes $5,000 in
about ten school weeks, and from then on, for those students, the staff
site's RESET ALL CASH (one movement of the whole balance) and staff-desk
store purchases over $5,000 are refused as "capped". Use the server instead:
`legacyPurge:zeroAllStudentCash` for a reset (a dry run first; `apply: true`
to clear; it files no year-end archive and takes no backup, so take those
first), and the student's own store purchase (`studentStore:purchase`, or
`studentStore:purchaseFor` from the command line) for a large item; neither
has the cap.

The one summary audit entry per payday stays off (`auditSummary`) until
the site that knows the `perfect_day_paid` action has reached the open tabs:
an older tab would show it on every teacher's home feed. The site stamped
`20261012c` knows it. Open tabs update themselves when idle, so switch it on
no sooner than the school day after that site is pushed:

```
npx convex run --prod perfectDay:configure '{"auditSummary":true,"actorName":"Your Name"}'
```

### Status and the admin's tools

```
npx convex run --prod perfectDay:status '{}'        # last runs, each date's verdict (counts), held students, paid-then-broken, next payday total, controls
npx convex run --prod perfectDay:ledgerCheck '{}'   # every attendance ledger row has its payment record (this week and last)
npx convex run --prod perfectDay:runNow '{"actorName":"Your Name"}'
npx convex run --prod perfectDay:decideAnyway '{"date":"2026-10-30","reason":"...","actorName":"Your Name"}'   # a date held as too perfect / a block missing
npx convex run --prod perfectDay:markNoSchool '{"date":"2026-10-30","reason":"...","actorName":"Your Name"}'   # refused while days are decided for it
npx convex run --prod perfectDay:resolveHeld '{"studentNumber":"...","date":"...","decision":"pay","reason":"...","actorName":"Your Name"}'
npx convex run --prod perfectDay:removeDays '{"studentNumber":"...","dates":["..."],"reason":"...","actorName":"Your Name"}'
npx convex run --prod perfectDay:correctPayout '{"txnId":"txn_...","removeDates":["..."],"reason":"...","actorName":"Your Name"}'
npx convex run --prod perfectDay:forfeitPending '{"from":"...","to":"...","reason":"...","actorName":"Your Name"}'   # counts; "apply":true forfeits
npx convex run --prod perfectDay:releaseUnchecked '{"date":"...","reason":"...","actorName":"Your Name"}'   # a date's days held only for the second check; counts; "apply":true releases
```

- **Held dates** (a read that would not hold still, far fewer students marked
  than usual, a block far below its usual level, or the Perfect Attendance
  screen disagreeing about more than 1% of the school) are tried again every
  run and expire unpaid once they leave the fifteen-school-day lookback (8/28's
  Promise Time PM was entered 7-12 school days late). The status lists every
  held date (`heldDates`) with its reason before it expires. A day that ran
  exactly the blocks of a day already decided (a Monday on the Tue/Fri bell,
  a normal day after stack or minimum days) is not short of a block; otherwise
  a block counts as expected only if it met on most days of the same weekday
  pattern. PowerSchool cannot tell "not entered yet" from "did not meet", so a
  day held for a missing block says both: if the block did not meet (an
  assembly without Power-Up), `decideAnyway` decides it.
- **Held only for the second check** (the attendance rebuild was down or
  writing): a run that can check releases them. They never expire, so an
  outage longer than the lookback forfeits nothing; they wait on the status's
  held list for `releaseUnchecked`, one call per date.
- **A date already decided whose re-read fails**, or that PowerSchool or the
  calendar now calls no school while days are pending, held or paid for it,
  stays decided with a note (the run tries a failed read again); its days
  stand until an admin takes them out. Once none is pending, held or paid,
  an admin's `markNoSchool` sticks.
- **A student who left and came back**: PowerSchool's students row holds the
  current enrolment only, so the days before they left are judged on their
  class records. A day already decided stands (and is paid) if those show a
  class that day; with no class record either it is held for an admin, never
  broken. Only an exit on or before the day breaks it.
- **A date already decided whose re-read is held** stays decided, with the
  re-read's reason: its days stand, but nothing is paid over what the read
  shows. A pending day for a student the read shows absent or tardy becomes
  broken, one the screen disputes is held, and a paid one goes on the
  paid-then-broken list.
- **Held students** (the screen disagrees about one student) are held alone;
  the rest of the school is decided.
- **A paid day that later breaks** is never taken back automatically. It is on
  the status's paid-then-broken list; `correctPayout` reverses the week and
  pays the days that stand, in one step. The Reverse button also works on the
  weekly row; `correctPayout` after it re-pays the good days.
- **No Hub record, or two**: the days stay pending and are counted, never paid
  to a guess and never dropped.
- Every admin act is in `perfectDayAudit`; runs in `perfectDayRuns`.

### What people see (the site half)

- **Students** (only when money will move for them: pilot or live, not a
  control): a "Perfect day – pending" line at the top of their Wildcat Cash
  activity, on the desk dashboard and on the wallet card, from the morning a
  day is decided: the days, the amount, and "Arrives Monday 10/19". No reason
  is ever shown for a day that is not there. The Monday payment is a line in
  their history, "Perfect attendance -- N days", by "Wildcat Hub
  (attendance)", with the days in its note.
- **Staff analytics leave it out**: the Overview tiles and week strip, the
  Staff tab, Trends, 5 to 1, one-to-one praise, whole-class detection, reach,
  expectation balance, quiet students and the home dashboard's "cash awarded
  this week" count only what adults award (kind award or deduct, and no
  `system:` marks). In the Staff tab's list of recent interactions the
  payment wears a grey "Attendance" badge.
- **It counts** in balances, Earned, Total in Circulation, the recount and
  drift check, and **both leaderboards** (they rank on Earned; owner's
  decision).
- **Accounts**: each student's Recent Activity and full history show the
  payment as "Perfect Attendance", read from the ledger, because it writes no
  audit entry per student.
- **Reverse** works on the weekly row and warns that it takes back every day
  in it.
- **Admins** see a read-only "Perfect-day award" card on the Cash Audit Log
  (`perfectDay:adminStatus`, admins and superadmins only): the mode, the last
  run, the last five dates with counts, held students and paid-then-broken
  days by name, the next payday and the controls. It changes nothing; it is
  empty until the award has ever been switched on.
- **Deploy order**: Convex first (the card's query and the summary entry's
  shape), then the site. A site without the backend shows no card and nothing
  else changes.
